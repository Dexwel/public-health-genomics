# Data policy

## The rule

**This repository contains only synthetic data.** No real person's genotypes, sequences, phenotypes, case records or contact details are, or ever will be, committed here - not even "anonymised", not even "just a few rows".

Why: genomic data are intrinsically identifying, cannot be changed if leaked, and also reveal information about relatives. A public repository is forever (history is public even after deletion).

## What you may add

| Allowed | Not allowed |
|---|---|
| Synthetic data generated by `scripts/make_toy_data.py` or a similar documented script | Real genotype, sequence or clinical data, even if "public" in another place |
| Summary statistics that are already public and licensed for reuse (cite the source, licence and date; keep < 1 MB) | Data from controlled-access resources (dbGaP, EGA, UK Biobank, GISAID sequences, ...) |
| Links to public datasets and how to request access | Outbreak data you are not authorised to share |
| Small public reference sequences (≤ 100 kb) with accession and licence | Files > 5 MB (CI blocks them) |

## Changing the toy data

The toy data are *deterministic*: the same seed produces byte-identical files. That lets anyone check that nothing was tampered with and lets every lab quote exact numbers.

If you need to change a dataset:

1. Edit `scripts/make_toy_data.py` (keep each dataset on its own random stream so changing one does not change the others).
2. Regenerate: `python scripts/make_toy_data.py`.
3. Regenerate checksums: `bash scripts/verify_data_reproducible.sh --write`.
4. Re-run every lab that uses the dataset and update **every number** quoted in the pages (search the repository for the old value).
5. Explain the change in the pull request. Data changes need maintainer approval.

## Answer keys

`data/**/answers/` holds the planted truth (which SNPs are causal, which isolates cluster, which rows are messy). Learners are told not to open it until the "check your answer" step. Keep the keys accurate and complete.

## Contributing a worked example (showcase)

Learner capstones can be added under `showcase/<your-name>-<track>/` as a README plus scripts and *small* outputs generated **only** from the toy data. Check the folder for personal data (names, emails, local paths) before opening the pull request.

## Using real data in your own work

Follow your institution's ethics approval, the data provider's access terms and national data-protection law. See Week 11. Do not paste real data into AI assistants or online tools unless your approvals allow it.
